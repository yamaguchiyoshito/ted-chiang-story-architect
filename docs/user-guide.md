## 1. そもそも「物語を設計する」とは

### 1.1 書く前に決めることがある

家を建てるとき、いきなりレンガを積む人はいません。まず「誰がどう住むか」を決め、間取り図を描きます。物語も同じで、本文（文章そのもの）を書く前に、次のようなことを決めておくと途中で迷子になりません。

- この物語は**何を問う**のか
- 最後に**どう答える**のか
- その答えにたどり着くのに**どの場面が必要**で、どれが要らないのか

これを一枚にまとめたものを、このスキルでは**設計図**と呼びます。このスキルが作るのは設計図までで、本文は書きません。本文は設計図を見ながらあなたが書きます（§8）。

### 1.2 アイデアはまだ物語ではない

「時間を巻き戻せる機械」「記憶を売買できる社会」──こうしたアイデアは面白いですが、それだけでは物語になりません。アイデアを説明するだけの文章は、読者にとって論文や設定資料と変わらないからです。

アイデアが物語になるには、少なくとも次の2つが必要です。

1. **読者の感覚に直接刺さる具体的な場面**（頭で理解する前に「うっ」とくるもの）
2. **その場面が、ある考えとぶつかって生まれる、逃げられない問い**

このスキルは、この2つを見つけてぶつける作業を、順序立てて手伝います。

> **確認**：設計図と本文の違いを一言で言えますか？ アイデアだけでは物語にならないのはなぜですか？

## 2. テッド・チャンと、このスキルが真似していること

### 2.1 どんな作家か

テッド・チャンはアメリカのSF作家です。長編を書かず、数十年かけて発表した短編・中編の数は多くありませんが、その多くが主要なSF賞を受けています。代表作「あなたの人生の物語」は映画『メッセージ』（2016年）の原作です。

作風の特徴は、**科学や哲学の厳密な考え**と、**人が生きることの痛みや喜び**が、一つの物語の中で切り離せない形で結びついていることです。「アイデアはすごいが人間が描けていない」あるいは「泣けるが中身がない」のどちらにもならない。その作り方には、インタビューや作品集の著者ノートで本人が語った、はっきりした習慣があります。

### 2.2 このスキルが真似している3つの習慣

| 習慣 | 中身 | スキルでの呼び方 |
|---|---|---|
| **長く頭に残る素材だけを使う** | 何年も頭から離れないアイデアだけを物語の種にする。すぐに物語にならなくても、在庫として持ち続ける | 素材選別（粘着R） |
| **絵と考えをぶつける** | 具体的なイメージと、科学・哲学の考えを組み合わせる。ただ並べるのでなく、互いに矛盾するようにぶつける | 二項合成（像A × 概念B → 核K） |
| **結末を最初に書く** | 本人いわく、最初に書くのはたいてい結末の段落。目的地を決めてから、そこへ向かう道筋を組み立てる | 因数分解・最短到達 |

たとえば「あなたの人生の物語」は、「終点を含めて全体の道筋が一度に決まる」という物理学の考え（変分原理）に長年惹かれながら、何年も物語にできなかったそうです。ある舞台を観て「避けられない喪失と、避けられない喜びを同時に抱える人生」という像を得たとき、ようやく二つがぶつかり、物語の核になりました。

スキルの中の説明には【本人発言】【逆算】という印が付いています。前者は本人が語った事実、後者は作品から推測して再構成したもので、両者を区別しています。

> **確認**：3つの習慣のうち、あなたにとって一番意外だったのはどれですか？（正解はありません。意外だったものほど、スキルの使用中に「なぜこれを聞かれるのか」と感じやすい箇所です）

## 3. ツールの前に知っておく考え方

スキルの中では「像A」「問いQ」のように、日本語の名前とアルファベットを組にした**変数**で各要素を呼びます。ここでは一つずつ意味を説明します。全体の一覧は §3.8 にあります。

### 3.1 素材：頭から離れないもの（粘着R）

物語の出発点は「面白そうなアイデア」ではなく、**気づくと何度も思い出してしまうもの**です。価値が高いかどうかは問いません。繰り返し戻ってくるかどうかが基準です。

- ○「子どもの頃に見た、閉館後の水族館の暗い水槽がなぜか忘れられない」
- ○「"全部記録されていたら、思い出は嘘になるのか"と何年も考えている」
- △「流行っているから AI の話を書きたい」（戻ってくる理由があなたの中にあるなら○）

素材は断片で構いません。一枚の絵、一つの疑問、一つの言葉だけで始められます。

### 3.2 像A と 概念B：絵と考え

素材には大きく2種類あります。

| | 像A（イメージ） | 概念B（考え・制約） |
|---|---|---|
| 何か | 説明なしに目に浮かぶ、1場面で完結する具体的な絵 | 科学・哲学・制度などから来る、逃げ道のない考え |
| 効き方 | 読者の感覚に直接効く | 読者の思考を追い込む |
| 良い例 | 自分の胸を開くと、心の正体であるテープが回っている男 | 生き物が食べているのはエネルギーではなく「秩序」である |
| 弱い例 | 「孤独な科学者」（ぼんやりして絵にならない） | 「テクノロジーは進化する」（ただの観察で、逃げ道がある） |

**見分けるコツ**：「写真に撮れそうなら像A、一文の命題として言えるなら概念B」。

概念Bでよくあるつまずきは、「記憶はあいまいだ」のような**観察**で止まってしまうことです。観察は「そうだね」で終わってしまいます。「もしそれが徹底されたら？」と押し進めて、「完全な記録が存在するとき、記憶を語り直すことは嘘になるのか」のように**逃げ道を塞いだ形**にすると概念Bになります。スキルはこの強化も手伝います。

### 3.3 衝突と混在：ぶつかっているか、並んでいるだけか

像Aと概念Bを組み合わせたものが**核K**（物語の核）です。ここで一番大事なのが、二つが**衝突**しているかどうかです。

| 状態 | 意味 | 結果 |
|---|---|---|
| ❌ 混在 | 像Aが概念Bの「例」になっているだけ／同じ方向を向いている | 概念の解説になり、論文のような物語になる |
| ✅ 衝突 | 概念Bが真だと、像Aが成り立たなくなる／あるいは逆説的に肯定される | 「では、どうするのか」という逃げられない問いが生まれる |

例：「自分の心を直接見る男」×「生命は秩序を消費して動いている」
→ 自分の内側を見ることが、自分を動かしている秩序が有限であること、つまり自分の終わりを見ることになってしまう。**見ることと知りたくないことが同じ一点で重なる**。これが衝突です。

衝突しない組み合わせは、無理に核にしません。スキルは「今回は保留して素材として持っておく」ことも正式な結果として扱います。チャン自身、何年も保留した素材があります。**保留は失敗ではありません。**

### 3.4 問いは1本、結末は最初に

核ができたら、そこから**問いQ**を1つだけ取り出します。

- 問いQは「はい／いいえ」で答えられない形にします。「AIは意識を持てるか」ではなく「〜とはどういうことか」「〜は成り立つのか」の形です。
- 問いが2本残ると、結末が2つに割れて作品がまとまりません。

次に、その問いへの答えである**結末E**を、本文より先に100〜200字で書きます。

**なぜ結末から？** 旅行にたとえると、目的地を決めずに歩き出すと、面白そうな路地に入り続けて帰れなくなります。目的地（結末）が先に決まっていれば、「この場面は目的地に近づいているか？」で、要る場面と要らない場面を判断できます。スキルが「結末Eを先に固定し、そこへ到達する道筋を設計する」と繰り返すのはこのためです。

結末Eには2つの約束があります。

1. **慰めで終わらない**：「きっといつか救われる」のような、読者を安心させるための言葉で締めない。
2. **引き受ける形にする**：喪失や矛盾が「消える」「乗り越えられる」のではなく、それを含んだ全体を**引き受ける**答えにする。

### 3.5 主人公は「一番損をする人」

主人公Hは、魅力的な人物ではなく、**この物語の世界で一番損をする立場の人**を選びます。ここでいう損は、事故や事件のような外から降ってくる不幸ではありません。**知っていながら、それでも引き受け続けること**の重さです。

「あなたの人生の物語」では、候補が次のように比べられています。

| 候補 | 損 | 判定 |
|---|---|---|
| 結婚して離婚する人 | 避けようと思えば避けられる | 弱い |
| 配偶者を亡くす人 | 一方的に奪われる | 中くらい |
| 子を亡くすと知りながら子を持つ人 | 喜びと喪失の両方を、知った上で引き受ける | 採用 |

### 3.6 世界のルール（機構M）と語り方（語りN）は「機能」で選ぶ

- **機構M**：問いを成り立たせるための、最小限の世界のルールです。「何が見える／見えないか」「何が何を引き起こすか」「何を犠牲にするか」の3点に絞ります。受け入れる「嘘」（現実にはない前提）は**1つだけ**にし、それ以外は現実どおりに詰めます。SFの舞台やジャンルは、このルールを説明しやすい場所として**後から**決まります。
- **語りN**：一人称か、手紙形式か、時間を行き来するか、といった語り方です。書きやすさや雰囲気ではなく、「読者がその問いを身をもって体験できるか」で選びます。

### 3.7 捨てた案を記録する（棄却ログ）

「なぜこれを選んだのか」は、「何を捨てたのか」と並べないと説明できません。スキルは、世界のルール・主人公・語り方について、採用案と一緒に**捨てた案とその理由**を必ず残します。あとで設計を見直すとき、この記録が一番役に立ちます。

### 3.8 変数の一覧

| 変数 | 読み方 | 一言で |
|---|---|---|
| 粘着R | ねんちゃく | 頭から離れない素材（入口のふるい） |
| 像A | ぞう | 目に浮かぶ具体的な絵 |
| 概念B | がいねん | 逃げ道のない考え・制約 |
| 核K | かく | 像Aと概念Bの衝突 |
| 問いQ | とい | 作品全体を貫く、1本の問い |
| 結末E | けつまつ | 問いへの答え（100〜200字、先に書く） |
| 機構M | きこう | 世界のルール3つ |
| 主人公H | しゅじんこう | 一番損をする人 |
| 語りN | かたり | 読者に問いを体験させる語り方 |

決める順番は **像A・概念B → 核K → 問いQ → 結末E → 機構M → 主人公H → 語りN** です。前の変数が次の変数の判断基準になるので、順番を飛ばすと判断の根拠がなくなります。

### 3.9 AIとあなたの役割分担

このスキルでは、AI（Claude）は**提案者**、あなたは**作者**です。

- AIは候補を出し、比べ、判定の根拠を示します。
- **結末Eだけは、必ずあなたが選んで承認します。** 結末は「作者が自分の名前で引き受けられる答え」であり、AIが代わりに決めてよいものではないからです。
- 設計図の各項目には【承認済み】（あなたが決めた）と【AI提案】（AIが出したまま）の印が付きます。どこが自分の判断かが一目でわかります。

> **確認**：次の2つはどちらが像Aでどちらが概念Bですか？ ①「雨の日にだけ開く古本屋」 ②「観測されるまで結果は確定しない」。そして、それぞれ衝突させるにはどうすればよさそうですか？（衝突の作り方に正解はありません。§5 で AI と一緒に探します）

## 4. 導入

このスキルは、`SKILL.md` と `references/` を含むこのフォルダ一式で動きます。

### Claude（claude.ai / デスクトップアプリ）で使う場合

1. このフォルダを ZIP にまとめる（フォルダごと圧縮）
2. Claude の設定画面にあるスキル（Skills）の項目から ZIP をアップロードする
3. スキルが有効になっていることを確認する

組織で配布されている場合は、すでに導入済みのことがあります。その場合は手順不要です。

### Claude Code で使う場合

このフォルダを次のどちらかに置きます。

- 自分の全プロジェクトで使う：`~/.claude/skills/ted-chiang-story-architect/`
- 特定のプロジェクトだけで使う：`<プロジェクト>/.claude/skills/ted-chiang-story-architect/`

画面やフォルダの場所は Claude のバージョンによって変わることがあります。見つからない場合は Claude の公式ヘルプで「Skills」を確認してください。

### 起動のしかた

特別なコマンドは要りません。「物語を考えたい」「このアイデアを短編にしたい」「テッド・チャン的な構成で書きたい」のように話しかけると、Claude がスキルを読み込んで始めます。うまく起動しない場合は「ted-chiang-story-architect スキルを使って」と明示してください。

## 5. 使ってみる：ステップごとの流れ

### 5.0 全体像

```
Step 0  モードを選ぶ
Step 1  素材を分ける ─────────── ゲート1：像Aと概念Bを決める
Step 2  ぶつけて核を作る ─────── ゲート2：核Kを承認する
Step 3  問いと結末を決める ───── ゲート3：結末Eを承認する（必須）
Step 4  ルール・主人公・語り方を決める
Step 5  要る場面・要らない場面を仕分ける
Step 6  設計図を受け取る
```

**ゲート**とは、あなたが選択・承認するまで先に進まない確認ポイントです。ゲートで「違う」と言えば、前のステップに戻ってやり直せます。遠慮は要りません。やり直しは設計の一部です。

以下、各ステップを「何が起きるか」「あなたがすること」「迷ったら」の3点で説明します。例として、素材「砂時計をひっくり返し続ける老人の画が頭から離れない」を使います（AIの応答は流れを示すための例で、実際の文面は毎回変わります）。

### Step 0：モードを選ぶ

**何が起きるか**：Claude が進め方を尋ねます。

| モード | 進み方 | 向いている人 |
|---|---|---|
| **対話モード**（推奨） | 3つのゲートで止まり、あなたが選びながら進む | はじめての人、学びたい人 |
| **おまかせモード** | 一気に設計図まで出す。結末Eは「仮固定」とされ、最後に承認を求められる | 全体像を先に見たい人 |

**あなたがすること**：はじめてなら対話モードを選んでください。このスキルの価値の多くは、ゲートで「選ぶ」体験にあります。

### Step 1：素材を分ける【ゲート1】

**何が起きるか**：あなたの素材が像A寄りか概念B寄りかを判定し、足りない側の候補を2〜3案出します。その前に、素材をそのまま使わず、**見方を変える操作**（転回）を試します。

- 抽象化：「この絵の本質は何か」を一文にして、別の具体的な絵に置き直す
- 反転：時間・立場・価値を逆にする
- 文字通り化：たとえ話を「もしそれが本当に物理的な事実だったら」に変える
- 立場の交換：一番損をする別の人から見る

> 例：「この画の本質は"終わりを知りながら反復を選ぶこと"だと読みました。衝突しうる概念Bの候補は ①熱力学第二法則 ②記憶の有限性 ③永劫回帰の倫理 です。元の画のどこに一番引っかかっていますか？」

**あなたがすること**：候補から選ぶか、「どれも違う」と言って理由を伝えます。**「元の素材のどこに惹かれているか」を言葉にする**と、転回があなたの関心からずれるのを防げます。

**迷ったら**：概念Bの候補が難しく感じても、全部を理解する必要はありません。「この言葉にはなぜか引っかかる」という感覚で選んで構いません。わからない用語は、その場で Claude に説明を求めてください。

### Step 2：ぶつけて核を作る【ゲート2】

**何が起きるか**：像Aと概念Bの組み合わせを複数試し、§3.3 の判定表で**衝突**しているものだけを残します。さらに「この衝突で一番損をするのは誰か」にすぐ答えられるかを確かめます（すぐ答えられないなら、どちらかが弱い）。

**あなたがすること**：示された核Kと、衝突だと判定した根拠を読み、納得できれば承認します。

**迷ったら**：「衝突していない」と言われたら、それは失敗ではなく情報です。選択肢は3つです：像A側を見直す／概念Bを差し替える／今回は保留する。保留した素材はメモしておき、別の日に別の考えと出会わせてください。

### Step 3：問いと結末を決める【ゲート3・必須】

**何が起きるか**：
1. 核から問いQを1本に絞ります。はい／いいえで答えられる形なら作り直し、大きすぎる問いは一人の人間が人生で答えるしかない大きさまで縮めます。
2. 結末Eの候補を**2〜3の方向**に分けて示します。

> 例（ここだけ「あなたの人生の物語」の問いを使います）：「問いQ『知っていても選ぶことは成り立つのか』への結末の方向：
> ①引き受け型：知ることと選ぶことは矛盾しない。全体を引き受けることが肯定になる
> ②反転型：選べないと知ったとき、はじめて"選ぶ"の意味が現れる
> ③拒絶型：成り立たない。だが、成り立たないと知りながら選ぶ姿を最後に置く
> どの方向なら、あなたが自分の名前で引き受けられますか？」

3. あなたが選んだ方向を、100〜200字に展開して承認を求めます。

**あなたがすること**：**「気持ちがいいか」ではなく「自分がそう考えると言えるか」で選んでください。** 混ぜたり、別の方向を指定したりしても構いません。

**迷ったら**：どれにも署名できないなら、それは問いQがまだあなたの問いになっていないサインです。「この問い自体がしっくりこない」と伝えて、問いから作り直しましょう。

### Step 4：ルール・主人公・語り方を決める

**何が起きるか**：
- **機構M**：核の前提が本当なら他に何が起きるかを5つ以上書き出し、問いに効く3つを「見える／起きる／失う」のルールに割り当てます。
- **主人公H**：損の強さを比べる段階表を作ります（§3.5 の表の形）。
- **語りN**：語り方の候補を2〜3出し、「読者が問いをどう体験するか」を1文で書けたものを採用します。

それぞれ、捨てた案と理由（棄却ログ）が一緒に出てきます。

**あなたがすること**：ここにゲートはありませんが、違和感があれば遠慮なく指摘してください。特に主人公Hについては、「この人の損は、自分で引き受けたものか、外から降ってきただけか」の視点で読むと判断しやすくなります。

### Step 5：要る場面・要らない場面を仕分ける

**何が起きるか**：場面の候補一つ一つに、結末Eに対する役割のラベルを付けます。

| ラベル | その場面がすること |
|---|---|
| 設置 | 世界のルールを、説明ではなく体験として読者に見せる |
| 転回 | 主人公の見方が変わり、問いが立ち上がる |
| 代価 | 主人公が損を引き受ける瞬間 |
| 回答 | 結末E。問いへの答えが、気持ちと理屈の両方で着地する |

**ラベルが付かない場面は削除候補**です。必要な場面3〜5つと、削除候補1〜2つが示されます。

**あなたがすること**：削除候補を見て「でもこれは残したい」と思ったら、その理由が「世界観が伝わるから」「調べたことが活きるから」「キャラが立つから」でないか考えてみてください。これらは典型的な口実です。世界観は「設置」の場面の中で伝えればよく、人物は損を引き受ける場面で立ち上がります。

設計図の読み方は次の章で説明します。

> **確認**：3つのゲートのうち、「必須」とされているのはどれで、なぜですか？

## 6. 出力された設計図の読み方

設計図は次の順に並びます。

| 見出し | 見るポイント |
|---|---|
| 凡例（冒頭1行） | 変数の対応表。迷ったらここに戻る |
| **二項合成** | 像A・概念B・核Kと、衝突の型（どうぶつかっているか） |
| **因数分解** | 問いQ・結末E・機構M（3つのルールの表）・主人公H・語りN |
| **棄却ログ** | 捨てた案と理由。採用理由はここで読み取る |
| **最短到達チェック** | 必要な場面（ラベル付き）と削除候補 |
| **整合チェック** | 問いQ・結末E・語りNの三つが噛み合っているか（✅／⚠️） |

各行末の印に注目してください。

- **【承認済み】**：あなたがゲートで選んだもの。あなたの判断です。
- **【AI提案】**：AIが出して、まだあなたが確かめていないもの。

【AI提案】が多い設計図は、まだ「あなたの物語」になりきっていません。一つずつ読んで、納得したら「これは承認」、違和感があれば §7 の方法で直しましょう。

**整合チェックが ⚠️ のとき**は、語り方が問いへの答えを読者に体験させられていない状態です。多くの場合、語りNを変えるか、問いQと結末Eを見直すと解消します。

---

## 7. 一部だけ直したいとき

「主人公だけ変えたい」「結末の方向を変えたい」といった部分的な修正ができます。そのまま伝えてください。

ただし、変数はつながっているので、一つを変えると他にも影響します。スキルは影響する範囲だけを再点検し、関係ない部分は変えません。

| 変えたもの | 影響する範囲 |
|---|---|
| 像A・概念B | ほぼ全部（核からやり直し） |
| 問いQ | 結末E・語りN・主人公Hの見直し |
| 結末E | 問いQとの整合・必要な場面・語りN ＋ **あなたの再承認** |
| 機構M | 主人公Hの損・語りN・舞台の選び直し |
| 主人公H | 損の段階表・結末Eに署名できるか |
| 語りN | 整合チェックのみ（影響は小さい） |

上流（表の上のほう）ほど影響が大きいことを覚えておくと、「どこを変えるべきか」を自分で判断しやすくなります。

## 8. 設計図ができたら

設計図は完成品ではなく、書き始めるための地図です。チャン自身の手順にならうと、次の順が書きやすくなります。

1. **結末の段落を書く**：結末Eの100〜200字を、実際の本文として書き直す
2. **冒頭を書く**：最初の「設置」場面
3. **残りの必要な場面を書く**：順番は自由。冒頭と結末をつなぐ場面だけを書く

書いている途中で新しい場面を足したくなったら、Step 5 のラベルを付けてみてください。付かなければ、その場面は棄却ログに記録して手放します。**調べて得た知識を登場人物にしゃべらせたくなったら要注意**です。チャンは5年分の言語学の調査のうち、場面として演じられる部分以外をほぼ捨てたと語っています。

## 9. 練習課題

スキルを使う前でも後でも取り組めます。答えを Claude に見せて、講評を求めても構いません。

1. **素材の棚卸し**：この1年で3回以上思い出したもの（絵・疑問・言葉）を5つ書き出す。それぞれ像A寄りか概念B寄りかを分ける。
2. **観察を制約に**：「人は変わらない」「SNSは人を孤独にする」を、「もし〜が徹底されたら」を使って、逃げ道のない一文に強化する。
3. **衝突判定**：「満開の桜の下で眠る人」を像Aとし、概念Bを3つ当ててみる。どれが混在で、どれが衝突か判定する。
4. **問いの作り直し**：「AIは意識を持てるか」を、はい／いいえで答えられない一人の人間の問いに作り直す。
5. **実例を読み解く**：「あなたの人生の物語」か「息吹」を読み、§3.8 の変数をすべて埋める。そのあと `references/examples.md` と見比べる。

## 10. よくある質問とつまずき

**Q. 素材が何もありません。**
「最近よく考えること」「子どもの頃から気になっていること」を雑談のように Claude に話してください。その中で繰り返し出てくるものが素材の候補です。練習課題1も役立ちます。

**Q. 科学や哲学に詳しくないと使えませんか？**
使えます。概念Bの候補は Claude が出し、説明もします。大事なのは知識の量ではなく、「これは気になる」というあなたの反応です。チャンの基準も「正しいかどうか」より「その前提で場面が思い浮かぶか」です。

**Q. SF 以外にも使えますか？**
手順そのものはジャンルを選びません。ただし、このスキルは「世界のルールを一つだけ現実から変える」設計を得意とするので、SF・幻想・寓話的な作品と特に相性がよいです。

**Q. 「衝突していません」と言われ続けます。**
像Aが抽象的すぎる（写真に撮れない）か、概念Bが観察止まり（逃げ道がある）のことが多いです。§3.2 の見分けるコツで確認してください。それでも立たない場合、その素材は今は保留が正解かもしれません。

**Q. 結末をどれにも決められません。**
問いQがあなたの問いになっていない可能性があります。「なぜこの問いが自分にとって大事か」を一文で言えるか試してください。言えなければ問いから作り直します。

**Q. 結末が暗くなってしまいます。**
「引き受ける」は「絶望する」ではありません。喪失を消さずに、それを含む全体を肯定する形があります（§3.4）。明るさではなく、あなたが同意できるかで判断してください。

**Q. おまかせモードで出た設計図をそのまま使っていいですか？**
使えますが、結末Eは「仮固定」です。必ず自分で読み、署名できるか確かめてください。【AI提案】の項目も同様です。

**Q. 本文も書いてもらえますか？**
このスキルの範囲は設計図までです。本文は設計図を見ながらあなたが書くことを前提にしています（§8）。

## 11. 用語集

| 用語 | 意味 |
|---|---|
| 設計図 | 本文を書く前に、問い・結末・ルール・主人公・語り方・必要な場面を決めた一覧 |
| 二項合成 | 像Aと概念Bの2つをぶつけて核Kを作ること |
| 因数分解 | 核Kから、問いQ→結末E→機構M→主人公H→語りNを順に取り出すこと |
| 最短到達 | 結末Eに向かう場面だけを残し、それ以外を削ること |
| 衝突／混在 | 2つの要素が矛盾を含んでぶつかっている／ただ並んでいるだけ |
| 転回 | 素材の見方を変える操作（抽象化・反転・文字通り化・立場の交換） |
| 文字通り化 | たとえ話やテーマを「もし物理的に本当だったら」の世界に変えること |
| ゲート | ユーザーが選択・承認するまで先に進まない確認ポイント |
| 保留 | 核にできない素材を、失敗扱いせず在庫として持っておくこと |
| 引き受け | 喪失や矛盾を消さず、それを含む全体を肯定する結末の形 |
| 一点の飛躍 | 現実と違う前提は1つだけにし、他は現実どおりに詰める原則 |
| 棄却ログ | 捨てた案と捨てた理由の記録 |
| 機能ラベル | 場面の役割（設置／転回／代価／回答） |
| 整合チェック | 問いQ・結末E・語りNの三つが噛み合っているかの確認 |
| 変更影響マトリクス | ある変数を変えたとき、どこを見直すべきかの対応表 |
| 【本人発言】／【逆算】 | 作家本人が語った事実／作品から推測した再構成 |

## 12. さらに学ぶ

スキルの内部で使っている資料は、人が読んでも学びになります。

| ファイル | 読むと得られるもの |
|---|---|
| `references/examples.md` | 「あなたの人生の物語」「息吹」の設計を変数ごとに分解した実例。捨てた案の具体例が豊富 |
| `references/variables.md` | 各変数の定義・判定基準・失敗パターンの詳細 |
| `references/steps/step1〜5-*.md` | 各ステップで AI が行っている操作の手順と、チャンの実例 |
| `SKILL.md` | スキル全体の手順と、出力フォーマット・絶対ルール |

作品そのものは、短編集『あなたの人生の物語』『息吹』（いずれも早川書房）で読めます。各作品の末尾にある著者ノートには、着想の経緯が本人の言葉で書かれており、このスキルの考え方の出どころを確かめられます。
